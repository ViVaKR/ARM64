# Vector

>D P를 쓸 때는 결과 레지스터 뒤에 "몇 비트짜리 데이터 몇 개로 채울 것인가"를 명확히 적어주어야 합니다. 128비트를 꽉 채우는 기준은 다음과 같습니다.
---
- V0.16B : 8비트(Byte)짜리 16개 칸을 모두 같은 값으로 채움
- V0.8H : 16비트(Halfword)짜리 8개 칸을 모두 같은 값으로 채움
- V0.4S : 32비트(Word/Single)짜리 4개 칸을 모두 같은 값으로 채움
- V0.2D : 64비트(Doubleword)짜리 2개 칸을 모두 같은 값으로 채움


ARM64(AArch64)에서 INS 명령어는 NEON(SIMD) 벡터 레지스터의 특정 위치(Element)에 값을 집어넣을 때(Insert) 사용하는 명령어입니다.
M4 Apple Silicon 같은 고성능 칩에서는 대량의 데이터를 병렬 처리할 일이 많은데, 이때 일반 레지스터(X, W)의 값을 벡터 레지스터(V)로 옮기거나, 벡터 레지스터끼리 특정 위치의 값을 복사할 때 핵심적으로 사용됩니다.
------------------------------
## 1. INS 명령어의 두 가지 형태와 기본 문법
INS 명령어는 크게 두 가지 방식으로 나뉩니다.
## ① 일반 레지스터 ➔ 벡터 레지스터로 삽입

INS Vd.Ts[index], Rn


* 동작: 일반 레지스터 Rn (또는 Wn)의 값을 벡터 레지스터 Vd의 index 번째 칸에 집어넣습니다.
* Ts (크기 지정): B(8비트), H(16비트), S(32비트), D(64비트)

## ② 벡터 레지스터 ➔ 벡터 레지스터로 복사 (이때는 보통 MOV로 씀)

INS Vd.Ts[index1], Vn.Ts[index2]


* 동작: Vn 레지스터의 index2 칸에 있는 값을 Vd 레지스터의 index1 칸으로 복사합니다.
* 참고: 실제 소스코드에서는 가독성을 위해 INS 대신 MOV Vd.Ts[index1], Vn.Ts[index2]라는 가상 명령어(Alias)로 더 자주 표현됩니다. (실제 컴파일되면 똑같이 INS로 바뀝니다.)

------------------------------
## 2. Apple Silicon(M4) 기준 실제 구문 예제
Apple Silicon 환경의 Clang 어셈블러 문법에 맞춘 실제 구문입니다. 이해를 돕기 위해 32비트 정수(정수형 S) 4개를 담는 128비트 벡터 레지스터 V0를 채우는 과정을 시뮬레이션해 보겠습니다.
```x86asm
.globl _test_ins_instruction
.p2align 2

_test_ins_instruction:
    // -------------------------------------------------------------
    // 초기 세팅: 일반 레지스터에 각각 다른 값을 넣습니다.
    // -------------------------------------------------------------
    MOV     W0, #10         // W0 = 10
    MOV     W1, #20         // W1 = 20
    MOV     W2, #30         // W2 = 30

    // -------------------------------------------------------------
    // ① 일반 레지스터 ➔ 벡터 레지스터 V0 (32비트 'S' 크기 배치)
    // V0.S는 총 4개의 칸(index 0, 1, 2, 3)을 가집니다.
    // -------------------------------------------------------------
    INS     V0.S[0], W0     // V0의 0번째 칸에 10을 삽입 -> [10,  0,  0,  0]
    INS     V0.S[1], W1     // V0의 1번째 칸에 20을 삽입 -> [10, 20,  0,  0]
    INS     V0.S[2], W2     // V0의 2번째 칸에 30을 삽입 -> [10, 20, 30,  0]

    // -------------------------------------------------------------
    // ② 벡터 레지스터 ➔ 벡터 레지스터 복사
    // V0의 1번째 칸(20)을 V1 레지스터의 3번째 칸으로 복사합니다.
    // -------------------------------------------------------------
    // 원래 명령어 구조: INS V1.S[3], V0.S[1]
    MOV     V1.S[3], V0.S[1] // V1의 3번째 칸에 20이 복사됨 -> [ 0,  0,  0, 20]

    RET
```

## 3. 크기 지정(Ts)에 따른 Index의 범위 규칙
벡터 레지스터 V는 총 128비트(16바이트) 크기 고정입니다. 따라서 쪼개는 크기에 따라 들어가는 Index의 개수가 달라집니다.

| 크기 지정 (Ts) | 데이터 타입 크기 | 128비트에 들어가는 개수 | 사용 가능한 Index 범위 |
|---|---|---|---|
| .B (Byte) | 8비트 (1바이트) | 16개 | [0] 부터 [15] 까지 |
| .H (Halfword) | 16비트 (2바이트) | 8개 | [0] 부터 [7] 까지 |
| .S (Word) | 32비트 (4바이트) | 4개 | [0] 부터 [3] 까지 |
| .D (Doubleword) | 64비트 (8바이트) | 2개 | [0] 또는 [1] |

⚠️ 주의: 만약 V0.S[4] 처럼 범위를 벗어난 인덱스를 지정하면 컴파일 에러(index out of range)가 발생합니다.

## 4. 왜 INS 명령어를 쓸까요? (실무 활용)
C언어에서 배열 구조체나 3D 그래픽스의 Vector4 (x, y, z, w) 같은 데이터를 다룰 때 매우 유용합니다.
일반 연산 장치에서 계산된 x, y, z, w 결과값들을 INS 명령어로 V0 레지스터 하나에 차곡차곡 모은 뒤, FADD(벡터 덧셈)나 FMUL(벡터 곱셈) 한 방으로 4개의 값을 동시에 연산(SIMD)하여 M4 칩의 강력한 병렬 처리 성능을 이끌어낼 수 있습니다.
INS 명령어와 반대로 벡터 레지스터에 있는 특정 칸의 값을 일반 레지스터로 꺼내오는 UMOV나 SMOV 명령어 예제도 함께 알아보실까요? 아니면 이 INS를 활용한 간단한 SIMD 벡터 연산 예제를 짜볼까요?
