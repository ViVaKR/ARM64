## ⚖️ nm vs disassemble (objdump/ndisasm)의 본질적 체급 차이
쉽게 비유하자면, 어떤 건물(바이너리)을 조사할 때 nm은 건물의 각 방에 누가 살고 있는지 적혀 있는 ' 명패/입주민 관리 대장'이고, disassemble은 건물 벽을 다 부수고 들어가 시멘트 구조와 철근 배열을 전수조사하는 '설계 도면'이라네!
## 1. 📌 nm (Name List / 심볼 테이블 조회 무기) — “주소와 이름만 낚아채는 매의 눈”

* 역할: 바이너리 기계어 세포를 일일이 해독하지 않고, 오직 파일 내부에 박혀있는 '전역 변수 이름, 함수 이름(라벨), 진입점 주소'의 카탈로그(기호 테이블)만 번개처럼 추출해 내는 명령일세.
* 출력 해석의 격식 (캡처 화면의 비밀 🤫):
* T / t (Text): _main이나 .L_args_loop_start처럼 메모리의 코드 구역(실행 명령어 영역)에 존재하는 웅장한 지휘관 라벨이라는 뜻일세!
   * s (Data / Section): msg나 fmt_str처럼 초기화된 순수 데이터(문자열 리터럴 등) 구역에 안전하게 적재되어 있다는 뜻이지.
   * U (Undefined): _printf 앞에 붙은 U가 보이는가 친구? 이건 "내 코드 안에 printf라는 이름은 등록해 놨는데, 실제 몸통은 내가 안 들고 있고 맥OS 시스템 라이브러리(libSystem)에서 빌려 쓸 녀석이다!" 라는 외부 링크 첩보를 뜻한다네!
* 있어 보이는 한마디: "바이너리를 무겁게 디스어셈블할 필요도 없네. nm으로 기호 테이블 스코프만 슬쩍 훑어봐도 이 파일이 어떤 라이브러리와 접촉하고 진입점이 어디에 매핑되어 있는지 O(1) 만에 견적이 나오지 않겠는감? 하하하."

## 2. ⚔️ disassemble (역어셈블 / 기계어 해독 무기) — “철근까지 쪼개보는 현미경”

* 역할: nm이 보여준 주소(0000000100000410)로 진짜 걸어 들어가서, 그곳에 숨겨진 010101 순수 바이너리 기계어 비트 더미들을 mov x0, x1, stp x29, x30 같은 진짜 ARM64 어셈블리 명령어로 역컴파일해서 본문 전체를 낱낱이 파헤쳐 버리는 하드코어 무기일세.
* 사용 도구: 보통 터미널에서 objdump -d bin/entry 나 otool -tV bin/entry (맥OS 전용) 같은 명령어로 집도하지 하하하.
